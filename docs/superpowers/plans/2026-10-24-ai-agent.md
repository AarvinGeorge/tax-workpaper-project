**Goal.** One investigation over the whole packet, deciding where to look, while deterministic tools do the exact
work; it finds what rules cannot settle (free text, unexplained leftovers) and proposes new checks in words. It adds
no reviewer work beyond today's AI rows, and it never blocks approval.

## What stays exactly as today (the safety model)
- Runs at intake, never from the UI. Output is the existing `AiPayload` (src/domain/ai/contract.ts); the backend
  re-checks schema and grounding (src/domain/ai/verify.ts); a person accepts or dismisses each suggestion; ✦ AI rows
  on Checks as now. The ledger is never in the prompt or the tools; it only scores (ai/harness.ts) and gates CI.
- The cloud cron keeps running the current per-document reader until the agent is measured and approved.

## Framework decision
Anthropic TypeScript SDK (`@anthropic-ai/sdk`, new dependency) and its tool runner (`client.beta.messages.toolRunner`)
with typed tools; not LangChain (an extra abstraction that lags new API features and weakens our injected-fetch
tests). Tests inject a fake transport through the SDK client's fetch option (verify the option name against the SDK
docs before use). Final answer: the structured payload via `output_config.format` (Fable confirmed tools and
structured outputs coexist); forced `tool_choice` is refused on current models, so the prompt steers and tools are
`strict`.

## Model and settings
`claude-opus-5-5` (the skill's default for agentic work; the reader stays on `claude-sonnet-5-5`), adaptive thinking,
effort `high`, the server-side refusal fallback enabled, a `--model` flag to measure Sonnet 5.5 against it. Guards: an
iteration cap on the runner, a wall-clock abort, a token budget logged per run; a partial or failed run never
overwrites the stored payload.

## Tools (thin wrappers over pure domain code; every result masked as today)
`get_line(key)`, `get_page(doc, page)`, `search_values(text)`, `find_fact_copies(line or doc)` (facts.ts),
`proofs_for_line(key)` (proofs.ts), `run_checks()` (findings already raised, so it does not repeat them),
`list_open_leftovers()` (lines with no proof and no finding; engine warnings no check covers; uncited money on
landed documents). Read-only; no tool returns a full identifier, account number or PIN; packet text in results is
marked as data, never instructions.

## Context (cached system block)
The packet README (field meanings), the firm's standards, the case brief (docs/brief.txt), and a short domain digest
distilled from docs/research (written once, committed beside the agent). Never docs/ground-truth, errors-found or the
ledger.

## Outputs
1. Suggestions: the existing row shape (kind, claims, evidence quotes, rationale, authority from the vetted list,
   confidence); quotes and refs verified by code as today.
2. Check proposals: a new optional list in the payload, structured (rule in words, the fact keys or fields compared,
   where it should fire, where it must stay silent); never code; shown nowhere in the app; reviewed offline and, if
   accepted, coded and tested like any check.

## Tasks (red first)
1. Dependency and tool wrappers: unit tests per tool on the real packet (masking, read-only, results bounded).
2. Agent loop module (`ai/lib/agent-core.ts`): runner with an injected fake transport; tests for the iteration cap,
   the abort, refusal and max_tokens stops, a malformed final payload (rejected, not stored), proposals validated.
3. CLI `ai/agent.ts` mirroring `ai/reader.ts` (writes `ai/eval/agent-suggestions.json` and run meta: tokens, cost,
   turns, seconds).
4. Measure (real money, Aarvin approves the budget first): run once on the real packet and once on the altered copy;
   harness scores; compare with reader-v2 on the same scorecard in a new section (handed-in numbers untouched).
5. Only if it beats the reader on recall with grounding at 100% and an acceptable time and cost: switch the stored
   payload and, if it fits within the function time limit, the cron route; else keep the CLI for intake runs.

## Out of scope
Running model-written code; the agent writing to the event log; blocking approval; a production background evaluator.

## Plan review (Fable 5.1, 24 Oct 13:19 EDT): APPROVE WITH CHANGES, all accepted
Verified against the SDK source (npm 1.3.0): the client's `fetch` option, `betaTool` (JSON Schema, no Zod),
`max_iterations`, structured output alongside tools; forced tool choice refused; Opus 5.5 effort must be set to high.
1. **No answer key through the tools**: `run_checks` returns findings without `ledgerIds` or ids that embed check ids;
   the blindness test greps every request body and the agent transcript for ledger ids and titles.
2. **Recall that cannot be gamed by echoing our checks**: a new scorecard tier, "ledger mistakes no deterministic check
   reaches", is the bar against reader-v2; suggestions whose claims equal an existing finding's are dropped. The blind
   22-of-27 was hand-scored, so it is not the baseline.
3. Every list tool takes a limit and a cursor, returns a total, and caps its bytes (the leftovers are ~166 items).
4. Offline tests inject a fetch returning real `Response` objects; `maxRetries` and `timeout` set explicitly.
5. One active-producer prompt-version constant before any switch, so the CI gate and the cron's idempotency agree.
6. The cron path is out of scope (a serial Opus loop will exceed 300 s); the agent runs from the CLI at intake.
Also: record the served model (a fallback may switch it); cache the growing transcript; scan every tool result for
SSN shapes and fail the run on a hit; no Zod; keep the "default" refusal fallback. Estimated $3-8 a run at Opus high;
measurement budget: two real-packet runs and one altered-copy run, approved by Aarvin before any spend.
